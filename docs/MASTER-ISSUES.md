## ISS-001 — جدول Friendship مفقود: ميزة الصداقات ميتة بالكامل
- **ID**: ISS-001 | **Severity**: P0 Critical | **Type**: BUG + DATA_ERROR
- **Module**: Backend `routes/studentFriendships.js` + Prisma schema | **Role**: STUDENT | **Page**: `/student-space/friendships` | **Feature**: قائمة/بحث/طلب/قبول الصداقات
- **Reproduction**:
  1. دخول `student@test.tn`.
  2. `GET /api/student/friends` → حاليًا `200 {friends:[],requests:[]}` (مضلل).
  3. `GET /api/student/friends/search?q=eleve01` → فشل.
- **Expected**: قوائم وبحث وطلبات تعمل.
- **Actual**: كل شيء فارغ/فاشل؛ الـtry/catch في الـroute يبتلع الخطأ ويعيد `[]`.
- **Evidence**:
  - سجل الخادم: `Invalid prisma.friendship.findMany() — The table (not available) does not exist` (`backend-audit.log:3`).
  - بحث آلي: صفر migration يحتوي `Friendship`.
  - فحص الانحراف: 71 model مقابل 71 جدولًا — **المفقود الوحيد هو `Friendship`**.
- **Root Cause**: أُضيف الـmodel إلى `schema.prisma` (~سطر 1377) دون migration.
- **Fix (للخطة)**: إنشاء migration للجدول + اختبار API حقيقي (list/search/request/accept) + مراجعة الـcatch الصامت (loggd بهدوء بدل الإخفاء).
- **Regression Test**: دورة صداقة كاملة بين تلميذين عبر API والواجهة — 200s وصفوف ظاهرة.
- **الإصلاح**: `prisma/migrations/20260926140000_friendships/migration.sql` (idempotent، مولَّد من `prisma migrate diff`) + سطر `runSqlFileOnce` في `src/index.js` ليُطبَّق على أي استضافة بلا `migrate deploy`.
- **القياس قبل/بعد**: قبل = `list 200 {[],[]}` + `search {users:[]}` + **`request 500`**؛ بعد = بحث ← `مستكشف المنصة` / `request 200` / `accept 200` / الطرفان يرى كلٌّ الآخر / `remove 200`.
- **تحقق حي بالواجهة**: تبويب الطلبات (1) ← زر القبول ← الأصدقاء (1) ← زر الحذف ← (0). والقاعدة عادت فارغة (0 صفوف).
- **اكتشافان أثناء الإصلاح**: (1) `api.delete` غير موجود في العميل (الاسم `api.del`) فزر حذف الصديق كان **لا يفعل شيئًا** وبصمت (`StudentFriendships.jsx:57`) — ISS-011. (2) `POST /friends/request` بـ`userId` ناقص أو نصّي يعطي **500** بدل 400 — ISS-010.
- **Regression Test**: `tests/friendships.test.js` — 9/9 (وجود الجدول، 401، بحث، إرسال، منع مكرر/النفس، قبول من صاحب الطلب فقط، رؤية الطرفين، رفض، إزالة).
- **Status**: **FIXED**

## ISS-003 — شهادات PDF تفشل دائمًا (العربية vs WinAnsi)
- **ID**: ISS-003 | **Severity**: P1 High | **Type**: BUG (printing/export)
- **Module**: Backend `services/certificateService.js:61` | **Role**: STUDENT | **Page**: `/student-space/certificates` → زر PDF
- **Reproduction**: افتح الشهادات (تظهر) → اضغط «تحميل PDF» → `500 {"error":"Failed to generate certificate"}`.
- **Expected**: ملف PDF عربي سليم.
- **Actual**: 500 لكل شهادة عربية.
- **Evidence**: سجل الخادم: `Certificate PDF error: Error: WinAnsi cannot encode "?" (0x0631)` — 0x0631 = حرف الراء.
- **Root Cause**: مكتبة PDF بترميز WinAnsi لا تدعم العربية؛ يلزم تضمين خط TTF عربي.
- **Fix (للخطة)**: تضمين خط عربي + اختبار توليد شهادة عربية/فرنسية + فحص رأس `%PDF`.
- **Regression Test**: تنزيل شهادتين (AR/FR) → ‏200 + `content-type: application/pdf`.
- **السبب الجذري الحقيقي (أدق مما سُجل أولًا)**: pdf-lib لم يكن يعرف العربية في هذا المسار: (أ) مجلد `backend/fonts/` الذي يبحث فيه عن `NotoSansArabic-*.ttf` **غير موجود**، (ب) حتى لو وُجد ملف، `pdf-lib` يرفض الخطوط المخصصة دون `registerFontkit`، (ج) `catch {}` كان يبتلع كل ذلك ويعود إلى Helvetica (WinAnsi).
- **الإصلاح**: المسار الأساسي صار محرك المتصفح نفسه الذي تستخدمه بقية وثائق المنصة (`browserPdf.js`) عبر قالب RTL جديد `rewardCertificateHtml` في `pdfTemplates.js` (أفقي، بنفس ألوان التخطيط الأصلي). المسار البديل باقٍ مع: تسجيل `fontkit`، البحث عن الخط في مجلدين، دالة `draw()` تقيس قبل الرسم فتتخطى الزخرفة غير المتوفرة بدل إسقاط المستند، و`console.error` صريح عند غياب الخط العربي.
- **مثبت بالإخراج**: PDF بحجم 152,839 بايت يبدأ بـ`%PDF-1.4`، والعربية فيه موصولة وباتجاه صحيح (الاسم/المادة/القسم/التاريخ/الأستاذ) — تمت معاينته كصورة.
- **Regression Test**: `tests/certificates.test.js` — 9/9 (قالب RTL، هروب الحقن، توليد PDF، 401، نوع غير معروف ← 400، الأنواع الثلاثة ← 200 + application/pdf، ترويسة اسم ملف ASCII).
- **Status**: **FIXED**
