# المرحلة 4.2 — ربط الاشتراكات + الفواتير الرقمية (منجزة)

تاريخ الإنجاز: 15-08-2026
النطاق: الدفعة 4.2 من المرحلة 4 — تحويل الاشتراكات إلى اشتراكات مدفوعة تلقائية.
المرجع: `docs/PHASES_SPLIT.md` — الدفعة 4.2.

## ما تم إنجازه

### 1. ربط الاشتراكات بعمليات الدفع (دفع ← تفعيل ← فاتورة)
- `createCheckoutIntent` يدعم الآن نوعَين من العمليات:
  - **`INITIAL`** (السلوك السابق): اشتراك بانتظار الدفع → دفع → تفعيل.
  - **`RENEWAL`** (جديد): اشتراك **نشط** → عملية تجديد → عند النجاح **يُمَدَّد الاشتراك للسنة الدراسية الموالية** تلقائيا (`nextSchoolYear` + حدود السنة)، مع تسجيل دفعة وفتورة.
- التمديد يحافظ على `ACTIVE` ويحدّث `SubscriptionRequest` المقترن و`accountStatus` للمستخدم.
- مسار `POST /api/payments/checkout` يقبل حقل `kind` (`INITIAL`/`RENEWAL`) و`discountCode`.

### 2. التجديد التلقائي + الإلغاء
- حقول جديدة على `Subscription`: `renewalEnabled` (افتراضي `true`) و`cancelledAt`.
- **مُجدوِل تلقائي** (`subscriptionRenewalService.startRenewalScheduler`): فحص دوري (افتراضي كل 6 ساعات، قابل للضبط عبر `RENEWAL_SWEEP_INTERVAL_MS`) يلتقط الاشتراكات النشطة التي:
  - ينتهي أجلها خلال **7 أيام**،
  - والتجديد التلقائي مفعّل فيها،
  - وليس لها نية تجديد معلّقة (`PENDING` + `metadata.kind = RENEWAL`) — **Idempotent**.
  ثم ينشئ لكل منها نية دفع تجديد ويرسل إشعارا للأولياء والمستفيد.
- مسارات تحكم يدوي:
  - `POST /api/payments/subscriptions/:id/cancel-renewal` — إلغاء التجديد التلقائي (المالك أو الولي أو إداري).
  - `POST /api/payments/subscriptions/:id/enable-renewal` — إعادة تفعيله.
  - `GET /api/payments/active` — الاشتراكات النشطة للمستخدم/الأبناء مع حالة التجديد ووجود نية معلّقة.
  - `POST /api/payments/admin/jobs/run-renewal` — تشغيل الفحص يدويا (إداري/نظامي) للاختبار والإدارة.
- تجربة المستخدم: زر **«تجديد الآن»** + زر تبديل التجديد التلقائي + زر **«أكمل الدفع»** عند وجود نية معلّقة.

### 3. الفواتير الرقمية PDF
- نموذج `Invoice` جديد: رقم فاتورة فريد (`INV-السنة-000001`)، المبلغ الأصلي، التخفيض، الضريبة، المجموع، كود التخفيض، العملة، التاريخ، ربط بـ`Payment` و`Subscription`.
- `invoiceService` يبني **فاتورة PDF عربية RTL** بخط Amiri (نفس خطوط التصدير الحالية) عبر `pdf-lib`، تتضمن: بيانات المستفيد، تفاصيل الاشتراك، التفصيل المالي، المجموع.
- تُصدر الفاتورة تلقائيا:
  - عند نجاح كل دفع إلكتروني (ابتدائي أو تجديد) عبر الـ Webhook، و
  - عند تسجيل الدفع اليدوي من لوحة الإدارة (`/api/admin/subscriptions/:id/pay`).
- مسارات الفواتير:
  - `GET /api/payments/invoices/mine` — فواتير المستخدم (أو أبنائه للولي).
  - `GET /api/payments/invoices/:id` — تفاصيل (المالك/الولي/إداري).
  - `GET /api/payments/invoices/:id/pdf` — تحميل PDF.
  - `GET /api/payments/admin/invoices` — كل الفواتير (إداري/نظامي).

### 4. أكواد التخفيض والمنح الدراسية
- نموذج `DiscountCode`: كود فريد، نوع (`PERCENTAGE` نسبة / `AMOUNT` مبلغ ثابت)، القيمة، حد الاستعمال (`usageLimit` + `usedCount`)، الصلاحية (`expiresAt`)، الحالة (`active`).
- تُطبق عند الدفع: يُحسب المبلغ النهائي (خلال `createCheckoutIntent`) وتُخزن تفاصيل التخفيض في `metadata`، وتُحتسب الاستعمالات **فقط عند نجاح الدفع** (لا تُستهلك عند الفشل).
- مسارات الإدارة (إداري/نظامي):
  - `GET/POST /api/payments/admin/discounts` — القائمة والإنشاء.
  - `PATCH /api/payments/admin/discounts/:id` — تعديل الوصف/الحد/الصلاحية.
  - `POST /api/payments/admin/discounts/:id/deactivate` — تعطيل فوري.

### 5. سجلات التدقيق الجديدة (AuditLog)
- `PAYMENT_RENEWAL_CREATED` — بدء عملية تجديد.
- `INVOICE_ISSUED` — إصدار فاتورة (مع رقمها ومصدرها).
- `SUBSCRIPTION_AUTO_RENEWAL_CANCELED` / `SUBSCRIPTION_AUTO_RENEWAL_ENABLED`.
- `DISCOUNT_CODE_CREATED` / `DISCOUNT_CODE_DEACTIVATED`.
- `RENEWAL_SWEEP_RUN` — تشغيل الفحص التلقائي.

### 6. الواجهة الأمامية (React)
- **مركز الدفع** `PaymentCenter.jsx`:
  - قسم **«الاشتراكات النشطة والتجديد التلقائي»**: حالة التجديد، زر تجديد الآن، زر أكمل الدفع لنية معلّقة، تبديل إلغاء/تفعيل التجديد.
  - قسم **«فواتيري الرقمية»**: جدول الفواتير مع زر **تحميل PDF** (عبر `api.download` بمصادقة Bearer).
  - حقل **«كود التخفيض / منحة دراسية»** في نافذة الدفع مع تمييز عملية التجديد (INITIAL/RENEWAL).
- **لوحة الاشتراكات** `AdminSubscriptions.jsx`:
  - إدارة أكواد التخفيض: إنشاء (كود/نوع/قيمة/حد/صلاحية/وصف)، قائمة، تعطيل.
  - جدول الفواتير الرقمية مع تحميل PDF.
  - زر **«تشغيل فحص التجديد الآن»**.
  - عمود حالة التجديد التلقائي في جدول الاشتراكات.

### 7. الاختبارات
- `backend/tests/subscriptions-invoices.test.js` — 13 اختبارا جديدا:
  - أكواد التخفيض: منع غير الإداري، إنشاء نسبة/مبلغ، رفض المكرر، تطبيق التخفيض (نسبة ومبلغ محدد)، رفض غير الصالح/المنتهي/المستنفد.
  - الفاتورة: إصدارها بعد نجاح الدفع مع التخفيض، زيادة عدّاد الاستعمال، قائمة المستخدم، تحميل PDF صالح، منع غير المالك، قائمة الإداري.
  - الربط والتجديد: إنشاء عملية `RENEWAL` على نشط ورفض غير النشط، دفع التجديد يمدّد السنة (2026-2027 ← 2027-2028) وينشئ دفعة وفتورة، إلغاء التجديد يمنع تجديدا جديدا ثم إعادة التفعيل تسمح به، منع غير المالك، فحص التلقائي (Sweep) لا يكرر النوايا.
  - الدفع اليدوي من الإداري يصدر فاتورة.

## كيف تجرّب المرحلة 4.2 (وضع الاختبار)
1. سجّل الدخول كولي: `parent@test.tn / parent123`.
2. افتح **«الدفع الإلكتروني»** من فضاء الولي.
3. في **«اشتراكات بانتظار الدفع»** اضغط «ادفع الآن»، أدخل كود تخفيض (أنشئه من لوحة الاشتراكات: `admin@education.tn / admin123`) ثم أكمل الدفع عبر المزود التجريبي.
4. تظهر **الفاتورة الرقمية** في قسم «فواتيري» — حمّلها PDF.
5. في **«الاشتراكات النشطة»** جرّب «تجديد الآن» أو بدّل حالة التجديد التلقائي.
6. الإداري يرى الفواتير وأكواد التخفيض وزر فحص التجديد في «الاشتراكات والمداخيل».
