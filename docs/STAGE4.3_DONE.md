# المرحلة 4.3 — لوحة المدير المالية (منجزة)

تاريخ الإنجاز: 15-08-2026
النطاق: الدفعة 4.3 من المرحلة 4 — إدارة مالية شفافة للمشرفين.
المرجع: `docs/PHASES_SPLIT.md` — الدفعة 4.3.

## ما تم إنجازه

### 1. لوحة مالية كاملة للإدارة (`/api/admin/finance`)
| المسار | الوظيفة |
|---|---|
| `GET /overview` | نظرة عامة: ملخص (إيراد الفترة/الشهر، نسبة النجاح، إرجاعات، تخفيضات، اشتراكات نشطة) + منحنى الإيراد الشهري (12 شهرا) + توزيع حسب الخطة والطريقة + آخر العمليات |
| `GET /reports` | بيانات التقرير المالي الكامل (ملخص + إيراد شهري + عمليات + فواتير + إرجاعات + أكواد التخفيض) مع تصفية الفترة |
| `GET /reports/pdf` | تصدير التقرير المالي **PDF** عربي RTL (خط Amiri) |
| `GET /reports/csv` | تصدير التقرير المالي **CSV** (ترميز UTF-8 مع BOM) |
| `GET /reconciliation` | **التسوية المالية**: مطابقة العمليات/الفواتير/نوايا الدفع + كشف الفروقات |
| `GET /refunds` | قائمة الإرجاعات |
| `POST /invoices/:id/refund` | إرجاع فاتورة (سجل إرجاع + تمييز الفاتورة `REFUNDED` + سجل تدقيق) |
| `GET /anomalies` | قائمة الشذوذات المالية (تصفية حسب الحالة والنوع مع ترقيم) |
| `POST /anomalies/detect` | تشغيل كشف الشذوذ يدويا |
| `POST /anomalies/:id/resolve` | معالجة/تجاهل شذوذ مع توثيق المسؤول |

- تصفية زمنية موحّدة لكل التقارير: `from` / `to` / `schoolYear` (مع رفض الجمع بين الفترة والسنة الدراسية).
- كل المسارات محمية بـ `requireRole('ADMIN','SUPER_ADMIN')`، وكل فعل مهم يُسجَّل في `AuditLog`.

### 2. نموذجا بيانات جديدان (تهجير `20260815080000_finance_dashboard`)
- `Refund` — عملية الإرجاع: الفاتورة، الدفعة، الاشتراك، المبلغ، السبب، المسؤول، التاريخ. يمكّن كشف الإرجاعات المتكررة.
- `FinancialAnomaly` — شذوذ مالي مكتشف: مفتاح فريد (يمنع التكرار)، النوع، الخطورة، الوصف، المرجع (`Subscription`/`Invoice`/`DiscountCode`/...)، الحالة (OPEN/RESOLVED/IGNORED)، المعالج، قرار المعالجة.

### 3. كشف الشذوذ (قواعد آلية قابلة للتوسعة)
| القاعدة | النوع | الخطورة | الشرط |
|---|---|---|---|
| إرجاعات متكررة على نفس الاشتراك | `REPEATED_REFUND` | مرتفع | ≥ 2 إرجاع خلال 90 يوما |
| محاولات دفع فاشلة متكررة | `REPEATED_FAILED_PAYMENT` | متوسط | ≥ 3 فشل خلال 30 يوما |
| عمليات دفع معلقة متعددة | `MULTIPLE_PENDING_INTENTS` | منخفض | > 2 نية معلّقة لنفس الاشتراك |
| استعمال مفرط لكود تخفيض | `OVERUSED_DISCOUNT` | متوسط | ≥ 5 استعمال خلال 24 ساعة |
| فاتورة بقيمة صفرية (منحة كاملة) | `FREE_INVOICE` | منخفض | فاتورة بمجموع 0 |
| دفع ناجح دون فاتورة | `SUCCEEDED_WITHOUT_INVOICE` | مرتفع | نية ناجحة دون فاتورة (خلل تسوية) |
| اختلاف مبلغ الفاتورة عن الدفع | `INVOICE_AMOUNT_MISMATCH` | مرتفع | `invoice.total ≠ payment.amount` |
| نسبة فشل مرتفعة لمزود | `PROVIDER_FAILURE_RATE` | متوسط | ≥ 5 عمليات حاسمة ونسبة فشل > 50% |
| موجة Webhook لعملات غير معروفة | `UNKNOWN_WEBHOOK_SURGE` | مرتفع | ≥ 5 أحداث مجهولة خلال 24 ساعة |

- القواعد تُشغَّل عند الطلب (`POST /anomalies/detect`) وتلقائيا بعد كل إرجاع فاتورة.
- المفتاح الفريد (`key`) يضمن عدم تكرار نفس الشذوذ؛ والمعالجة تحفظ القرار والمسؤول، فلا يعاود الظهور.

### 4. الواجهة الأمامية (React)
- صفحة جديدة `frontend/src/pages/director/FinanceDashboard.jsx` (تبويب «اللوحة المالية» في فضاء الإدارة، رابط `/director/finance`) بأقسام:
  - **نظرة عامة**: بطاقات ملخص + منحنى الإيراد الشهري + توزيع حسب الخطة والطريقة + أحدث العمليات ونوايا الدفع، مع حقول تصفية الفترة/السنة الدراسية.
  - **العمليات والفواتير**: جدول نوايا الدفع (حالة/مزود/نوع) + جدول الفواتير (تحميل PDF + زر إرجاع) + جدول الإرجاعات.
  - **التسوية**: بطاقات المجاميع + إشعارات الفروقات + جداول «عمليات بلا فواتير» و«اختلافات المبالغ».
  - **كشف الشذوذ**: قائمة الشذوذات بالخطورة والحالة + أزرار «معالجة»/«تجاهل» + زر «تشغيل الكشف الآن» + عدّاد الشذوذات المفتوحة في التبويب.
  - **التقارير المالية**: معاينة ملخص التقرير + أزرار تصدير PDF / CSV بالفترة المحددة.
- الرابط أُضيف في `DirectorDashboard.jsx` (متاح للمدير العام والنظامي فقط عبر `canManageFinance`).

### 5. الاختبارات
- `backend/tests/finance-dashboard.test.js` — 11 اختبارا جديدا:
  - حماية الوصول (ولي/أستاذ ← 403) لكل المسارات المالية.
  - النظرة العامة بعد دفع ناجح (المجاميع + المنحنى + الفواتير).
  - التقرير المالي + تصدير PDF صالح وCSV عربي.
  - تصفية الفترة/السنة الدراسية (استبعاد عمليات خارج النطاق).
  - التسوية: كشف عملية بلا فاتورة وفروق الجمل، ثم تطابق تام بعد دفع ناجح.
  - الإرجاع: تسجيل إرجاع، تمييز الفاتورة، منع الإرجاع المزدوج (400)، سجل تدقيق، منع غير الإداري.
  - كشف الشذوذ: محاولات فشل متكررة ← `REPEATED_FAILED_PAYMENT` + معالجتها دون تكرار، فاتورة مجانية ← `FREE_INVOICE` مع سجل تدقيق للكشف، إرجاعان على نفس الاشتراك ← `REPEATED_REFUND`.

## كيف تجرّب المرحلة 4.3 (وضع الاختبار)
1. سجّل الدخول كمدير عام: `admin@education.tn / admin123`.
2. افتح **«اللوحة المالية»** من فضاء الإدارة (`/director/finance`).
3. في «العمليات والفواتير»: حمّل فاتورة PDF أو أجرِ **إرجاع** لفاتورة مدفوعة.
4. في «كشف الشذوذ»: اضغط «تشغيل الكشف الآن» ثم «معالجة»/«تجاهل» أي شذوذ.
5. في «التقارير المالية»: حدّد فترة أو سنة دراسية ثم صدّر **PDF** أو **CSV**.
6. في «التسوية»: تحقق من تطابق العمليات والفواتير وكشف الفروقات.
