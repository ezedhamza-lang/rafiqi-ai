# معايير محتوى رفيقي التعليمية (ذاكرة المشروع — يُلتزَم بها دائماً)

> هذه قواعد ثابتة اتفقنا عليها. لا يُعاد شرحها؛ كل عمل محتوى جديد يلتزم بها.

## 1) الهدف
تحسين المحتوى القديم وإعادة بنائه **بالكامل**. **نُبقي على عناوين الدروس فقط** (والمعرّفات/المرجع الرسمي)، ونُستبدل المضمون.

## 2) الطابع الموحّد لكل الكتب
**كل الدروس في كل المواد (رياضيات/قراءة/علوم/إنتاج/قصص) تُعرض بنفس طابع «سلسلة النصوص»** — أي نمط ورقة الاختبار:
1. **سند/نصّ أوّل** (`story_text` أو `passage`) + صورة كبيرة واحدة معبّرة.
2. **أسئلة مسترسلة** تُبنى **على نفس السند** (الفهم والاستيعاب) ثم أسئلة **متنوّعة تشبه ما يَرِد في الامتحان**.
3. تنويع الأنواع (حسب كل درس/سند): **اختر (MCQ) · صحيح/خطأ · علّل · صل/ربط (match) · لوّن/ارسم · أكمل/أصلح · رتّب · أكتب/أُنتج**.
4. خاتمة: عبرة/خلاصة (moral/summary) عند الاقتضاء.

## 3) كثرة الأسئلة وتنوّعها
كل درس = مجموعة أسئلة **كثيفة ومتنوِّعة** مشتقّة من السند والصورة (لا سؤالين فقيرين). تُراعى مستويات: فهم ← تطبيق ← تحليل/إنتاج.

## 4) لا صوت
**لا يوجد زر/مكان قراءة صوتية** في أي درس/كتاب. أي عارض تُدمَج فيه الدروس يجب أن يُلغي `speechSynthesis`/أزرار الاستماع.

## 5) الصور
- أسلوب كرتوني موحّد:
  `flat vector children-book illustration, soft pastel palette, rounded shapes, thick clean outlines, warm light, white background, no text, no letters, no watermark, 4:3`
- **لا نص داخل الصورة**.
- تُخزَّن في `frontend/public/curriculum/<year>/<subject>/` وتُخدم على `/curriculum/<year>/<subject>/...` (لا تضعها في `backend/uploads` فهو مُستثنى من Docker).
- مسار الصورة في JSON: `image: "/curriculum/..."`.

## 6) التقنيات
- محتوى يُكتب داخل ملفات `backend/curriculum/<year>/<subject>-units.json` بنفس مخطّط السلسلة (`units[].lessons[]`).
- التحقق: `node -e require(...)` لصحة JSON + اختبار محرّك المحتوى + بناء الواجهة.
- كل دفعة: commit + push مستقلّ بعد اختبار.

## 7) سير العمل مع المعلّم (المستخدم)
المعلّم يُولّد الصور بأوامر أكتبها له ويضعها في `D:\mon projet\rafiqi-incoming` ← أنقلها وأدمجها وأدفع.
