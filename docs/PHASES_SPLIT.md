# تقسيم المراحل إلى دفعات عمل (Batch Split Plan)

وثيقة عمل لتقسيم المراحل المتبقية من خارطة طريق «بوابة رفيقي للحياة المدرسية»
إلى مراحل فرعية قابلة للتسليم والاختبار بشكل مستقل، بحيث تنجز كل دفعة وحدها
(شيفرة تعمل + اختبارات خضراء + تجربة متكاملة) دون انتظار بقية الدفعات.

المرجع: «خارطة طريق تنفيذ تحسينات» — المراحل 1 و2 منجزة بالفعل.

---

## المرحلة 3: التكليفات المنزلية + التحليلات + التواصل
الميزانية الكلية: ~1-1.5M توكن | الأولوية: عالية
تنقسم إلى **3 دفعات**:

### الدفعة 3.1 — نظام التكليفات الأساسي (الجوهر)
الميزانية: ~500-600K توكن
**الهدف**
بناء حلقة التكليف الكاملة: إسناد ← إنجاز ← تصحيح آلي ← إشعار.
**نطاق العمل**
- نماذج بيانات Prisma: `Assignment` / `Submission` / `Grade` + تهجير Migrations.
- مسارات CRUD محمية بالأدوار (أستاذ يسنّد، تلميذ ينجز، ولي يتابع).
- تصحيح تلقائي للأسئلة الموضوعية (اختيار متعدد، صح/خطأ، ملء فراغ).
- واجهة الأستاذ: إنشاء/تعديل تكليف، جدول متابعة، تصحيح يدوي، إسناد لقسم.
- واجهة التلميذ: استقبال التكليفات، الإنجاز، مراجعة التصحيح.
- واجهة الولي: متابعة التكليفات والدرجات ومواعيد التسليم.
**المخرجات**
وحدة تكليفات متكاملة مع تصحيح آلي وواجهات الأدوار الثلاثة.
**معايير القبول**
السيناريو الكامل ينجح: أستاذ يسنّد ← تلميذ ينجز ← تصحيح آلي ← الولي يرى النتيجة.

### الدفعة 3.2 — التقارير التحليلية والتصدير
الميزانية: ~300-400K توكن
**الهدف**
تحويل بيانات التكليفات إلى رؤى مفيدة للأستاذ والولي.
**نطاق العمل**
- تقرير تحليلي لكل تلميذ: نقاط القوة/الضعف حسب المواد.
- منحنى الأداء عبر الزمن (خط بياني بسيط دون مكتبات ثقيلة أو عبر Chart.js إن أمكن).
- تنبيهات تعثر مبكرة (نسبة إنجاز منخفضة / درجات متراجعة).
- تصدير الدرجات Excel / PDF من لوحة الأستاذ.
**المخرجات**
لوحة تحليلات + تصدير الدرجات.
**معايير القبول**
تقرير تلميذ واحد يعرض القوة/الضعف والمنحنى، وتنبيه تعثر يظهر عند توفر البيانات.

### الدفعة 3.3 — المحادثة الفورية (ولي ↔ أستاذ)
الميزانية: ~200-300K توكن
**الهدف**
تواصل مباشر ولحظي بين الولي والأستاذ داخل المنصة.
**نطاق العمل**
- غرفة محادثة عبر Socket.io (نفس البنية الموجودة في `/ws` الحالي).
- إشعار فوري عند وصول رسالة جديدة (شارة عدّاد في الهيدر).
- حفظ سجل المحادثات في قاعدة البيانات.
**المخرجات**
محادثة فورية تعمل مع إشعارات.
**معايير القبول**
ولي وأستاذ يتبادلان الرسائل لحظياً وتظهر الإشعارات والعدّاد.

> ملاحظة: تُسلَّم الدفعات تباعاً، ويمكن التوقف بعد 3.1 لتسليم القيمة الأساسية.

## المرحلة 4: المدفوعات الإلكترونية
الميزانية الكلية: ~0.8-1.2M توكن | الأولوية: متوسطة
تنقسم إلى **3 دفعات**:

### الدفعة 4.1 — تكامل مزود الدفع (Sandbox)
الميزانية: ~300-400K توكن
**الهدف**
فتح باب الدفع الفعلي بأمان في وضع الاختبار.
**نطاق العمل**
- تكامل Stripe أو بوابة STB (وضع اختبار) + واجهة تجريدية Provider Interface.
- معالجة Webhooks (نجاح/فشل/إلغاء).
- تأمين: CAPTCHA + سجلات تدقيق (Audit Logs).
**المخرجات**
دفع تجريبي يمر عبر المزود ويعود عبر Webhook.
**معايير القبول**
اشتراك تجريبي يُنشأ وتبلغه Webhook بنجاح (Sandbox).

### الدفعة 4.2 — ربط الاشتراكات + الفواتير
الميزانية: ~300-400K توكن
**الهدف**
تحويل الاشتراكات الحالية إلى اشتراكات مدفوعة تلقائية.
**نطاق العمل**
- ربط الاشتراكات (تلميذ 147 د.ت / أستاذ 50 د.ت) بعمليات الدفع.
- تجديد تلقائي + إلغاء.
- فواتير رقمية PDF + أكواد تخفيض/منح دراسية.
**المخرجات**
دورة كاملة: دفع ← تفعيل ← فاتورة ← تجديد/إلغاء.
**معايير القبول**
اشتراك مدفوع يُفعّل تلقائياً، فاتورة تُصدَر، تجديد يعمل، إلغاء يُعالَج.

### الدفعة 4.3 — لوحة المدير المالية
الميزانية: ~200-300K توكن
**الهدف**
إدارة مالية شفافة للمشرفين.
**نطاق العمل**
- لوحة مدير: العمليات، الفواتير، التقارير المالية، التسوية.
- كشف شذوذ (عمليات مشبوهة/إرجاعات متكررة).
**المخرجات**
لوحة مالية كاملة.
**معايير القبول**
المدير يعاين العمليات والفواتير ويصدر تقريراً مالياً.

> ملاحظة: تتطلب حسابات تاجر خارجية — البدء بـ Sandbox ثم الإنتاج.

## المرحلة 5: الحصص المباشرة + التواصل الفوري
الميزانية الكلية: ~1-1.5M توكن | الأولوية: متوسطة
تنقسم إلى **3 دفعات**:

### الدفعة 5.1 — البث المباشر وجدولته
الميزانية: ~400-500K توكن
**الهدف**
حصة حية بفيديو وصوت داخل المنصة.
**نطاق العمل**
- تكامل مزود فيديو (LiveKit / Agora / Jitsi) عبر واجهة تجريدية قابلة للتبديل.
- جدولة الحصص + تسجيل تلقائي متاح بعد انتهاء الحصة.
**المخرجات**
حصة مباشرة تعمل + تسجيل متاح.
**معايير القبول**
حصة حية بفيديو وصوت تستوعب 30 مستخدماً، والتسجيل متاح بعد الانتهاء.

### الدفعة 5.2 — تفاعلات الحصة الحية
الميزانية: ~300-400K توكن — ✅ **مُنفّذة بالكامل** (انظر `docs/STAGE5.2_DONE.md`)
**الهدف**
تفاعل داخل الحصة.
**نطاق العمل**
- دردشة حية خلال البث + رفع اليد + مشاركة شاشة.
**المخرجات**
تفاعلات الحصة كاملة.
**معايير القبول**
تلميذ يرفع يده ويشارك شاشته ويكتب في الدردشة أثناء الحصة.
- الحالة: **مكتمل** — 9 اختبارات جديدة (الإجمالي 124/124 ناجحاً)، الواجهة والأنماط والـ Swagger محدّثة.

### الدفعة 5.3 — الإشعارات الموحدة + مركز الرسائل
الميزانية: ~200-300K توكن — ✅ **مُنفّذة بالكامل** (انظر `docs/STAGE5.3_DONE.md`)
**الهدف**
قناة تواصل موحدة لكل المستخدمين.
**نطاق العمل**
- نظام إشعارات متعدد القنوات: Push + Email (+ SMS اختياري).
- مركز رسائل داخلية (الإعلانات، الإشعارات، المراسلات).
**المخرجات**
مركز رسائل + إشعارات عبر القنوات.
**معايير القبول**
إعلان يصدر من الإدارة فيصل المستخدمين كإشعار داخل المنصة.
- الحالة: **مكتمل** — 11 اختبارًا جديدًا (الإجمالي 135/135 ناجحًا)، الواجهة والأنماط والـ Swagger محدّثة.

## المرحلة 6: المحتوى التعليمي التفاعلي
الميزانية الكلية: ~20-30M توكن (تُنفذ على دفعات متتابعة)
الأولوية: استراتيجية — القلب
تظل مقسّمة كما في الخارطة الأصلية مع تفصيل التنفيذ الداخلي:

### الدفعة 6.1 — بنية الدرس التفاعلي
- صيغة JSON موحدة (عناوين، شرح، أمثلة، تمارين، أنشطة).
- مكوّن عرض عام (عربي RTL، صوت، رسوم).
- مخرج: قالب درس + مكوّن عرض يعمل.
- قبول: درس نموذجي يعرض ويُنجز من الشرح إلى التمرين.

### الدفعة 6.2 — توليد المحتوى (الأضخم — تُنفذ على موجات)
الموجة 6.2أ: سنة أولى × المواد (عربية، فرنسية، رياضيات، إيقاظ علمي، تربية إسلامية/مدنية، تربية تشكيلية) بجودة عالية.
الموجة 6.2ب: سنة ثانية × المواد.
الموجة 6.2ج: سنوات ثالثة ← سادسة (تغطية أوسع).
- قبول: محتوى السنتين الأوليين متاح للاستعمال الفعلي من التلاميذ.

### الدفعة 6.3 — بنك أسئلة + محرك امتحانات
- بنك أسئلة لكل مادة + توليد امتحانات مخصصة + تصحيح آلي.
- قبول: امتحان يولَّد ويصحح آلياً.

### الدفعة 6.4 — فيديوهات قصيرة
- فيديوهات 3-5 دقائق لكل درس (تقديري).
- قبول: فيديو لكل درس نموذجي.
- الحالة: **مكتملة (بنية الكتالوج + المشغّل)** — كتالوج مصادر خارجية بميتاداتا موحّدة ومشغّل يدعم يوتيوب/Dailymotion/Vimeo/ملفات مباشرة، وتبويب «فيديوهات» في عارض الدروس + صفحة «الفيديوهات» في فضاء التلميذ (انظر `docs/STAGE6.4_DONE.md`). **الكتالوج فارغ عمدًا** ويُملأ لاحقًا من مصادر رسمية معتمدة بموجب قاعدة «لا نختلق محتوى».

### الدفعة 6.5 — تعلم تكيفي أولي
- تصعيب/تسهيل الأسئلة حسب الأداء (Spaced Repetition).
- قبول: مستوى السؤال يتغير حسب إجابات التلميذ.

### الدفعة 6.6 — ربط المحتوى بالتقدم والشارات
- ربط المحتوى بتتبع التقدم + الشارات والنقاط.
- قبول: إتمام درس يمنح نقاطاً وشارات (الربط بواجهات المرحلة 2).

> ملاحظات حرجة: كل درس ~20-50K توكن → الميزانية تنتج ~600-1000 درس.
> البدء بسنة أولى + ثانية بجودة عالية أفضل من تغطية سطحية للكل.
> التدقيق البشري مقابل المنهاج الرسمي إلزامي قبل النشر (جهد غير محسوب بالتوكنات).

## المرحلة 7: الذكاء الاصطناعي
الميزانية الكلية: ~0.8-1.2M توكن + تكلفة API متجددة
الأولوية: تمييزية
تنقسم إلى **3 دفعات**:

### الدفعة 7.1 — AI Tutor للتلميذ
الميزانية: ~300-400K توكن
**الهدف**
مساعد يشرح ويصحح للتلميذ بأسلوب مبسط.
**نطاق العمل**
- روبوت محادثة (سؤال ← شرح مبسط ← تصحيح) مرتبط بمحتوى المرحلة 6.
**المخرجات**
AI Tutor يعمل داخل فضاء التلميذ.
**معايير القبول**
تلميذ يسأل شرحاً فيحصل على إجابة صحيحة مبسطة.

### الدفعة 7.2 — AI Assistant للأستاذ
الميزانية: ~300-400K توكن
**الهدف**
توليد المحتوى البيداغوجي بسرعة.
**نطاق العمل**
- توليد خطط دروس، أسئلة، ملخصات، وشرائح عرض (التوسع في مولّد PPT الحالي).
**المخرجات**
مساعد أستاذ متكامل.
**معايير القبول**
الأستاذ يولّد خطة درس كاملة بنقرة.

### الدفعة 7.3 — AI للولي + محرك التوقع
الميزانية: ~200-300K توكن
**الهدف**
ذكاء تنبؤي يستبق المشاكل.
**نطاق العمل**
- تلخيص تقرير الابن + اقتراح أنشطة للولي.
- محرك توقع التعثر المبكر من بيانات الأداء والحضور.
- تعلم تكيفي متقدم بالاستفادة من بيانات المرحلة 6.
**المخرجات**
توقع تعثر + ملخصات للولي.
**معايير القبول**
الولي يتلقى ملخصاً واضحاً وتنبؤاً مبكراً عند خطر تعثر.

> ملاحظة: مفتاح LLM يوفره صاحب المشروع — لا يُستعمل أي مفتاح من بيئة التنفيذ.

### قواعد العمل الإلزامية (كما في الوثيقة الأصلية)
- لا كسر للـ API الحالي — أي تغيير موثق ويعالج التوافق.
- لا أسرار أو مفاتيح في الكود أو في ملفات الريبو.
- كل ميزة جديدة مقرونة باختبارات ومعايير قبول.
- الدفعات لا تُدمج قبل استيفاء معايير القبول الخاصة بها.
- أي عمليات حذف تتطلب تأكيداً مسبقاً.
- الالتزام بهيكلية الأدوار الستة بأقل صلاحية ممكنة.
- كل دفعة تسلّم وحدها: شيفرة تعمل + اختبارات خضراء + تجربة متكاملة + تحديث الملف الكامل للتحميل.
